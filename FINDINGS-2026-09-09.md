# What the 2026-09-09 investigation measured

Three questions were asked of this repo at once: replace the confidence score with
something that does not imply precision it lacks; report per-paper token spend; and
stop trusting the supplementary download blindly. Answering them required measuring
things nobody had measured, and most of those measurements are not derivable from the
code — they come from the 392-paper corpus, from 12 paired same-input run directories
under `~/.manuscript-harvest/perturbation/`, and from 3,667 persisted `claude -p`
transcripts under `~/.claude/projects/`.

This file is the record of those measurements. It is written before any of the work
lands, because a finding that lives only in a chat window is a finding that has to be
paid for twice.

**Provenance.** Numbers below are marked `[direct]` where they were produced by
running the check in this working tree, and `[agent]` where a subagent produced them
with a cited file. Where two independent agents produced the same number it is marked
`[agent x2]`. Nothing here is an estimate unless it says so.

## 1. The confidence number

### 1.1 It has exactly one consumer

`paper_confidence` is compared to a number in exactly one place in the entire pack:
`task/report.py:105-106`, which assigns triage tier 3 (`yes` with
`paper_confidence < 0.6`, the threshold coming from `task/report.yaml:53`). `[agent]`

Nothing else branches on it:

- The determination provably does not read it. `task/decide.yaml:13-18` declares the
  complete input set Stage A and Stage B read — `processing_status`,
  `text_completeness`, `has_single_cell_assay`, `perturbation_present_any_assay`,
  `perturbations[].single_cell_paired`. Confidence is not among them. `[agent]`
- It does not gate review. `pe/validate.py:398` sets `needs_review = True`
  unconditionally, with the comment "every paper gets human review regardless of
  confidence". Verified in the live 392-row CSV: `needs_review` is True on 392/392. `[agent]`
- No module in `pe/` reads the value. `pe/summarize.py`, `pe/compare.py`,
  `pe/audit.py`, `pe/pack.py`, `pe/prepare.py`, `pe/pending.py` and
  `pe/run_headless.sh` contain zero references. `[agent]`
- It appears in none of the 21 corpus counters at `task/report.py:211+`, which
  `prompt.md` step 11 calls "the acceptance criteria for the version, not
  decoration". `[agent]`

Its whole behavioural footprint is one triage tier, one CSV sort position, two CSV
columns, and three human-readable screen lines.

### 1.2 The rubric defines three bands; the model emits thirty values

`prompt.md:344-346` gives three qualitative bands — 0.80-1.0, 0.40-0.79, 0.20-0.39 —
described by evidence shape (explicit statement / inferred pairing / weak signal).
Nothing in the spec distinguishes 0.85 from 0.92. Over 392 papers the model emits
**30 distinct values**. `[agent]`

The one threshold that reads the number, 0.6, matches none of the three band edges
and sits *inside* the middle band. `task/report.yaml:50-53` says so explicitly: "a
FOURTH threshold, matching none of prompt.md's three rubric band edges". `[direct]`

So whether a paper enters the review queue is decided by where in the 0.40-0.79 band
the model happens to land — which is the part of the number the spec never defined.

### 1.3 It is not validated at all

`paper_confidence` is not in `task/record.yaml:62` `required_fields` and has no
`field_checks` entry. Probed against the live code: absent, `null`, `"0.4"`, `"low"`,
`5.0` and `-1` all pass validation silently. A `yes` paper with a malformed
confidence sinks to tier 9 — the bottom of a 392-row queue — with no flag. A boolean
`False` scores tier 3, because `isinstance(False, int)` is true and `False < 0.6`. `[agent]`

### 1.4 How unstable it actually is

Pooling all nine paired acceptance re-runs on identical input
(`work-accept-v00{12,14,15,16,17,18,19,20,21}-r1` vs `-r2`): **n=319 pairs, only 117
(37%) identical**, mean |delta| 0.038, median 0.020, p90 0.10, **max 0.62**. On the
305 papers where the determination did not change, 13 (4.3%) still moved confidence
by >= 0.1 — pure noise with no accompanying judgment change. `[agent]`

The tier it controls churns worse than the number does: across those same paired
runs, **11 of the 16 papers that entered tier 3 in either run flipped in or out of
it**. `[agent]`

`RESCORE-v0.0.21.md:77-84` already tabulated five papers moving on byte-identical
input (`assembled_text_sha256` verified identical, `truncation.rung` 0 in both):

| paper | `text_completeness` r1 -> r2 | `paper_confidence` r1 -> r2 |
|---|---|---|
| `s41591-021-01586-1` | truncated -> full | 0.35 -> 0.90 |
| `2020.03.04.976407` | truncated -> full | 0.45 -> 0.85 |
| `2023.03.06.531398` | truncated -> full | 0.35 -> 0.88 |
| `2024.10.18.618987` | truncated -> full | 0.45 -> 0.90 |
| `science.abo1984` | unknown -> full | 0.30 -> 0.88 |

**Five of those six large swings are not confidence judgments.** The rubric says a
`no`/`unclear` on partial text belongs at 0.20-0.39, so confidence is being derived
by rubric lookup from `text_completeness` — a *different* unstable self-report. Any
scheme that reads that field inherits its wobble. `[direct, reading RESCORE + prompt.md:346]`

### 1.5 Three results that invert the obvious fix

**(a) Binning is free, and it is most of the win.** Binning the *existing* number
into prompt.md's own three bands gives **91.1% identical (336/369) across the paired
runs, 94.2% when the determination held** — against 37.1% for the raw number. A
harness-derived `evidence_grade` design scored 93.5%. The elaborate replacement buys
2.4 points over rounding. `[agent]`

**(b) But an ordinal is a near-constant column, and it hides the wobble.** **317 of
392 papers (80.9%) fall in the top band**, and **100 (25.5%) sit within 0.06 of a
band edge**. A label reading "high" for four papers in five is not a triage signal,
and its movement is concentrated exactly at the edges — where a reader can no longer
see how close the paper was to flipping. A three-level label over the same unstable
judgment is *less* falsifiable than the number. `[agent]`

**(c) A purely harness-derived grade passes on nothing.** Across all 392 v0.0.21
records: `quotes_failed`=0, `quotes_wrong_source`=0, `perturbations_dropped`=0,
`consistency_flags`=0, `evidence_flags`=0. Only `stage_b_capped`=15 and
`determination_changed_by_harness`=1. All 101 positives carry `assay_evidence` on
every paired-yes perturbation. **There is no harness fact that discriminates among
positives.** A fully-derived grade scores every positive `stated` and tier 3 holds
zero papers. `[agent]`

Running one such design's own verification predicate over the real records: 127 of
179 paired-yes perturbations fail its `group_named` substring test and **59 of 101
positives would grade `inferred`**, taking tier 3 from 7 papers to 59 — 58% of
positives, which is the "a tier holding most papers is not a queue" failure that
`task/report.py:99-102` already documents for the unrestricted tier 2. `[agent]`

### 1.6 The finding that decides the design

**The number is the best instability predictor in the record.** Measured over 369
paired papers: `paper_confidence < 0.8` selects 110 and catches **21 of 22
determination flips**. The union of every harness fact (`unclear`, `stage_b_capped`,
text-not-full) selects 34 and catches **10 of 22**. `[agent]`

So the field is meaningless *as a displayed quantity* and simultaneously the best
routing signal available *as an internal screen*. Deleting the display is reversible;
deleting the field is not.

### 1.7 The actual complaint underneath

**The determination itself flips on byte-identical input: 22 of 369 same-input
paper-pairs (6.0%) change `perturbation_present`.** `[agent]`

Confidence is the messenger. Renaming the doubt field does not touch this.

### 1.8 Dead code found along the way

`downgrade_confidence: 0.2` (`task/record.yaml:219`, read at `task/rules.py:102`)
rewrites a dropped perturbation's confidence at `task/rules.py:642-643` and saves
`confidence_original`. **Zero perturbations have been dropped across all 30 stored
work directories**, so the path has never executed, and `confidence_original` is read
by nothing. Its YAML comment describes a threshold; the code is an unconditional
overwrite that would *raise* an item at 0.1 to 0.2. `[agent]`

`max_pert_confidence` (`task/report.py:196`) is a write-only CSV column with no
reader. `[agent]`

### 1.9 Every human-facing surface

Two CSV columns (`task/report.yaml:83`, `:109`); the review-screen record line
(`task/rules.py:434`); Screen A per-record and per-perturbation
(`task/screens.py:132`, `:139`); Screen C header (`task/screens.py:197`);
`SKILL.md:175`; `PRESENTATION-DRAFT.md:411-452` (a whole slide, ending "Never use it
as a threshold"); and **`REVIEW-HANDOUT.md:30-39`**, a live curator-facing document
that was untracked and therefore missing from the first survey. It already warns
curators the number "is not stable ... has moved it from 0.35 to 0.90. Treat it as a
rough sort order, nothing more." `[direct]`

`manuscript_harvest/` contains zero references to perturbation confidence. Every
`confidence` in that package is the extract layer's, which is **already categorical**
(`declared`/`ok`/`low`/`none`, `high`/`low`/`confirmed`) — an in-repo precedent. `[agent]`

## 2. Token and cost accounting

### 2.1 Nothing is captured today

`pe/run_headless.sh:88-92` invokes:

```
claude -p "$task" --model "$MODEL" --permission-mode acceptEdits \
  --allowedTools Read Write Bash Grep --output-format text >"$log" 2>&1
```

`--output-format text` means stdout is only the agent's final reply. **Every log in
the 392-paper v0.0.21 run is 5 bytes containing `DONE`.** The only token-ish
reference anywhere in the repo is `chars // 4` as an input-size guess
(`pe/pending.py:121`, `pe/prepare.py:322`). `[agent]`

### 2.2 The envelope has exactly what is wanted

`claude -p --output-format json` returns a result object carrying `total_cost_usd`,
`duration_ms`, `duration_api_ms`, `ttft_ms`, `num_turns`, `session_id`, `is_error`,
`api_error_status`, `permission_denials`, `subagent_stats`, a cumulative `usage`
block, and `modelUsage[<model>]` with `inputTokens`, `outputTokens`,
`cacheReadInputTokens`, `cacheCreationInputTokens`, `costUSD` and
`costBasis: "list"`. `[direct, probed twice on this machine]`

Verified on an **agentic** call (Write tool, `--permission-mode acceptEdits`,
`num_turns`=2): the file is still written, stdout is still clean JSON, and `usage` /
`modelUsage` **aggregate across turns**. The nested `usage.iterations` array does
*not* — it listed one of two iterations and must not be summed. `[direct + agent]`

### 2.3 History is already on disk

`pe/run_headless.sh:34` does `cd "$ROOT"`, so every `claude -p` session persisted to
`~/.claude/projects/-Users-gabdank-github-Lattice-Data-manuscript-harvest--claude-skills-perturbation-detection/`
— 3,667 transcripts, 1.0 GB. Each assistant line carries `message.usage` and a
`requestId`; the first user message embeds the prompt-file path, so work-dir + DOI
are recoverable. `[agent]`

Reconstructed `work-corpus-v0021-r1`: **392 papers, 535 attempts (143 papers retried),
4,579 real model requests, 9,158 input / 3,660,624 output / 295,151,111 cache-read /
37,446,096 cache-write tokens, $613.60 at list price, mean $1.565/paper**, 13.0 h
summed agent wall-clock. `[agent x2 — two agents reconstructed this independently and
agreed to the cent]`

**So the backfill works today with zero change to the invocation.**

### 2.4 Prices, solved not guessed

Opus-5 list prices solved exactly against the CLI's own `total_cost_usd` on
independent probes: input $5, output $25, cache-read $0.50, **cache-write $10.00**
per Mtok. `[agent]`

$10 is the `ephemeral_1h` rate. These runs report `ephemeral_1h_input_tokens`
exclusively and zero `ephemeral_5m`, so pricing the 37.4M cache-write tokens at the
5-minute $6.25 rate **understates the run by ~$140**. Read the `cache_creation`
sub-object; do not collapse to `cache_creation_input_tokens`.

### 2.5 Where the money actually goes

Spend split: **cache-write 61.0%, cache-read 24.1%, output 14.9%, input 0.007%**. `[agent]`

Least-squares over 392 papers: **cost = $1.151 + 3.20e-6 x chars**. At the median
108,994-char paper the variable part is $0.35 of a $1.50 bill — **77% of a paper's
cost is fixed**. Smallest decile (median 50,492 chars) costs $0.92; largest (median
255,697 chars) costs $2.32. Five times the text for 2.5x the money. `[agent]`

Correlations: **r(requests, cost) = 0.885** against **r(chars, cost) = 0.503**
(r-squared 0.25). Median 11 requests per paper, max 38 — for a task that is "read one
file, write one JSON". 98.4% of cache reads are a session re-reading its own context. `[agent]`

**Consequence for the report design:** a per-1k-characters normaliser tightens the
p10-p90 spread only from 2.53x to 2.08x — an 18% reduction. The actionable driver is
turns, not size. Lead with requests.

**Consequence for replication costing:** because cost is mostly fixed per paper,
re-running a screened subset costs roughly proportional to paper *count*. Re-running
the ~110 papers under `conf < 0.8` at N=2 is on the order of **$165**, not a
size-weighted share of $614.

### 2.6 Traps for any reader of this data

- **Dedupe by `message.id`.** Streaming re-emits the same assistant message on
  multiple JSONL lines. One sampled transcript had 20 assistant lines carrying 13
  unique ids; naive summing gave 21,139 output tokens against a true 11,045 — a 91%
  overcount. `[agent]`
- **Filter `model == "<synthetic>"`.** The corpus run's transcripts contain **145**
  injected "You've hit your session limit" messages with all-zero usage. Total
  assistant messages 4,724; real requests 4,579. The difference is exactly the 145
  wasted spawns the runner's own comment records. `[agent]`
- **Retry logs are destroyed, transcripts are not.** `>"$log"` truncates, and 143
  papers were retried. Per-paper usage must accumulate across attempts. `[agent]`
- **There is a second, uninstrumented invocation path.** `pe/extract_workflow.js`
  drives one `agent()` per paper via the Workflow tool and returns no usage fields.
  Instrumenting only the shell script leaves it silently uncovered. `[agent]`
- **The AUTHOK preflight** (`run_headless.sh:198`) is one real `claude -p` per run
  that no per-paper report will attribute.

## 3. Supplementary coverage

### 3.1 What exists today, and what it does not check

Fetch writes `manifest.json` with a `supplementary[]` array carrying `path`, `bytes`,
`sha256`, `index`, `url`, `label`, `tier`, `content_type` and `original_name`. The
publisher-side filename is preserved on all 5,301 corpus entries. `[agent]`

But `supplementary_status` has ten values and **`expected_but_missing` fires on 0 of
392 papers**, because it depends on Europe PMC's boolean `hasSuppl` and
`suppl_flag_is_authoritative` correctly distrusts that flag in exactly the cases
where supplements are most likely missing. Distribution: `fetched` 138,
`fetched_unverified` 240, `none_listed` 11, `partial_failure` 2, `none_retrieved` 1. `[agent]`

`fetched` is the strongest word in the taxonomy and still does not mean "we have
everything the paper references" — it means one tier's own index bounded the set it
enumerated. `10.1016/j.cell.2020.11.028` reads `fetched` / "supplements complete"
with 3 of 14 JATS-advertised items on disk. `[agent]`

Existing QC answers other questions: `validate.py` is only about the PDF;
`revalidate.py` re-asks identity from bytes; `orphans.py` finds files with no manifest
entry (the inverse); `store.manifest_is_complete` only checks named paths exist.
**Nothing asks whether the text references a supplement we never downloaded.** `[agent]`

### 3.2 The naive check is badly wrong in both directions

A first-pass prototype matching in-text references against *content labels inside
extracted supplementary text*, over all 392 papers: 11 papers reference no
supplementary material; **189 fully resolved; 192 with at least one unresolved
reference** (10 of them with zero supplementary files fetched at all); 6,899
referenced items, 1,487 (21.6%) unresolved. Distribution is bimodal — 189 at fraction
1.00, 28 at fraction 0.00. `[direct]`

But **file counts are not a valid proxy for item counts, in either direction**:

- `10.1002_ctm2.1356` references 15 items and fetched **one** `.docx` — which
  contains all 15, headed "Supplementary Figure 1".."Supplementary Table 5" where the
  text says "Figure S5". A file-count check reports 15 missing; the truth is zero. `[direct]`
- `10.1016_j.cell.2020.08.013` looks like 12 referenced vs 4 fetched and is actually
  missing all **seven** supplemental figures. `[agent]`

### 3.3 Two real, objective gaps

**Never fetched (structural, near-zero false positives).** Joining the 2,306 distinct
JATS `<supplementary-material>` hrefs to manifest entries: 2,054 (89.1%) match
exactly, 4 only after dropping the extension, **248 (10.8%) have no manifest entry at
all**, and 69 (3.0%) joined then were deleted by the text-bearing filter. The 248
break down `.xlsx` 136, `.pdf` 36, `.mp4` 24, `.csv` 21, `.jpg` 7 — **mostly data,
not the images the filter is supposed to drop**. Roughly 48 articles. `[agent]`

**A concrete, unrecorded fetch failure.** `10.1101_2023.03.06.531398` fetched
`media-14.xlsx` and `media-15.xlsx` from URLs ending `/DC14/` and `/DC15/`. bioRxiv
numbers supplements from DC1, so at least 13 files were never fetched — and the
manifest records only those two entries, with no gap noted. The main text references
38 items; none resolve. `[direct]`

### 3.4 The two gaps are different, and conflating them misreports

Across the 23 corpus papers whose bundle caption declares a figure range ("Document
S1. Figures S1-S7"), defining captions inside the fetched PDF bind **183 of 192**
declared figures. The 9 failures cluster on 2 papers
(`10.1016_j.devcel.2020.11.010`: 4 of 6; `10.1016_j.xcrm.2026.102651`: 4 of 5) —
**the file was fetched, the legend was not extracted, and a naive check reports it as
never fetched**. `[agent]`

### 3.5 What is recoverable, per paper

- 151 papers: exact JATS chain `in-text string -> rid -> id -> href`. All 7,926
  `<xref ref-type="supplementary-material">` resolve; zero dangling rids. `[agent]`
- 79 papers: JATS caption label -> href (Springer/BMC style, no xrefs).
- 118 papers: `landing.html` only.
- 20 papers: JATS href with an unlabelled caption.
- 10 papers: nothing structural — regex only.
- 15 papers: no supplements fetched.

**Filenames self-describe in only 18% of fetched files** (Science 355/422 = 84%,
Nature 31/1493 = 2%, Elsevier 17/646 = 3%). Positional inference is provably unsafe:
across 239 Elsevier entries with a parseable "Type SK" caption the offset N-K is +1 in
94 cases, 0 in 58, and also -4, -2, -1, +2, +3, +4, +7. **`mmc4` is not `Table S3`.** `[agent]`

### 3.6 False-positive sources, measured

- **Self-references inside supplements** — the largest bucket, 25,984 mentions in
  `role=='supplement'` blocks. `[agent]`
- **"Related to ..." clauses.** In `10.1016_j.cell.2020.08.013` the only occurrences
  of Figures S1/S4/S5/S7 anywhere in the supplements are inside "Table S2. ... Related
  to Figures 5, 6, 7, S3, S4, S5, and S7". A naive presence check reports **4 of the
  7 genuinely-missing figures as present**. A check must distinguish a caption that
  *defines* an item from a label mentioned inside another item's caption. `[agent]`
- **Boilerplate**: "The online version contains supplementary material available at
  10..." x121, and a bare "Supplementary Materials" heading x228.
- **Reference lists**: not mainly "Supplementary Table" but journal abbreviations
  ("Eur Urol Suppl", "21(Suppl 5)") and Cell Press KEY RESOURCES TABLE rows citing
  *another* paper's Table S5. The KRT is not always in `section=='references'`.
- **Data-availability sections**: 260 mentions.

### 3.7 Vocabulary variety, measured

28,285 main-text mentions corpus-wide. `Figure SN` 5,888 hits/199 papers; `Extended
Data Fig. N` 4,586/98; `Table SN` 3,015/172; `Supplementary Table N` 2,753/139;
`Supplementary Fig. N` 2,658/109; `Supplementary Data N` 1,207/52; `Supplemental
Fig/Table` 447/21; `Source Data Fig N` 361/28; `SI Appendix` 318/8; `Data SN` 286/30;
**PLOS-reversed (`S1 Data`, `S4A Fig`) 254/20**; `Additional file N` 205/4; EMBO
Expanded View (`Fig EV1`, `Appendix Figure S1`) 157/5. `[agent]`

**PLOS's reversed order is invisible to a type-then-number regex and silently zeroes
an entire paper** — the same never-fires failure shape as the `source` field bug. The
same item also has different surface forms in text, in the supplement, and in the
JATS caption ("Figure S5" = "Supplementary Figure 5" = "Supporting Information").

### 3.8 Populations that break the assumptions

- **124 of 392 papers are PDF-only** — no JATS at all. 10 have neither JATS nor
  landing HTML.
- **42 are preprints** (10.1101, 10.64898, 10.21203), typically shipping
  undifferentiated `media-N.pdf` with no JATS supplementary-material, no landing
  labels and no caption.
- **12 papers hit the `max_files: 50` cap.** `apply_files_cap` records a dropped
  *count*, never the names, so their missing count is unknowable from the manifest.
- **12 papers have manifests that disagree with `supplementary/` on disk.**
- **2,295 of 5,301 entries have no `path` key** — they are `drop_media` policy
  removals carrying `removed`/`removed_reason`. Treating a path-less entry as missing
  fires on 138 articles that are correct by design.

## 4. The fence: which changes need a model run

This decides the cost of everything above, and no design surfaced it unprompted.

`pe/prepare.py:78-93` sends the model **only** two slices of `prompt.md`: the
contents of the first fenced block after `## Instruction prompt`, and the slice
between `## Output schema` and `## Toggle decisions`. Anchors are declared in
`task/task.yaml:80-83`. `[direct]`

Measured line numbers in the current `prompt.md`:

| region | lines | seen by the model |
|---|---|---|
| Instruction prompt (fenced) | 92-420 | **yes** |
| — Confidence rubric | 341-349 | **yes** |
| Output schema slice | 424-509 | **yes** |
| Step 10, triage ladder | 623-655 | no |
| Step 11, corpus counters | 656+ | no |

So: **moving `pack_sha256` is not the same as changing what the model is asked.**
`PACK_GLOBS` is `("prompt.md", "task/*.yaml", "task/*.py")` (`pe/pack.py:81`), so any
edit to the ladder, the CSV columns or the counters moves the hash and needs a
`task_version` bump — but cannot move a determination, and re-validating the stored
raw JSON (pure Python over `work/raw`, restamping at `pe/validate.py:394`) is
sufficient.

**Only an edit inside lines 92-420 or 424-509 forces the acceptance protocol at
`prompt.md:657`** — preserved baseline, run twice, ~$614 and ~13 h.

## 5. The largest evidence hole, which nobody asked about

`INCLUDE_KINDS` at `pe/paper_text.py:45` excludes `kind='table'`. Supplement-role
blocks carry **54.9M characters — 29.0M of them table cards (53%), which never reach
the model.** `[agent]`

Consequence, measured by replaying `build_sources` over all 392 papers: 3,642
supplementary files seen, 751 kept, 22 dropped as admin, 3 as duplicates, and
**2,866 dropped as "tiny" — 2,833 of them with the exact string `(0->0 chars)`**,
i.e. spreadsheet-only files reduced to nothing by the kind filter. That is 1,935 xlsx
+ 486 zip:xlsx + 191 zip:csv + 126 csv + 56 xls files. These are the donor and sample
metadata sheets. `[agent]`

A further 1,370,165 main-text characters are dropped for `section=='supplementary'`,
615,354 of them PDF-derived — labelled by the heuristic tracker that
`section_audit.py` structurally cannot score. `[agent]`

The reported reason for excluding tables is Cell Press KEY RESOURCES TABLE false
positives, which argues for excluding *that card*, not every card. **This is ~100x
larger than the ~250 never-fetched files, it moves determinations, and it needs a
curator ruling before code.**

Related, and unmodelled: 118 archive supplements exist, 19 over 50 MB, the largest
1,422 MB. Expansion caps at 25 members and depth 2 — **2,457 declared members yielded
766 reads**. Every proposed ledger counts a zip as one entry, so none can say
"fetched, but 20 of its 25 members were skipped".

## 6. Traps recorded for whoever implements this

- **Deleting a pack YAML key without its reader crashes at import.**
  `task/report.py:38` reads `low_confidence_yes` and `task/rules.py:102` reads
  `downgrade_confidence` as bare dict subscripts into module constants. Removing
  either key alone raises `KeyError` for every entry point — including `pe.pending`,
  whose job is to report that the pack is broken.
- **The triage ladder has exactly one free slot (8)** (`task/report.yaml:22`), pinned
  to `prompt.md` step 10 by `tests/test_prompt_pack_agree.py:235-249`. It renumbered
  once at v0.0.10 and that is documented twice as a trap. Vacate a slot; do not
  renumber.
- **`tests/test_organism.py:205`** uses a `conf=0.45` -> tier 3 record as the premise
  for proving tier 7 does not displace tiers 1-6. Removing tier 3 requires
  re-fixturing it or that guard silently stops guarding.
- **`tests/test_prompt_pack_agree.py:253-261`** binds `low_confidence_yes` to the
  literal `< 0.6` in prompt.md step 10 — a two-sided drift guard; both sides move in
  one commit or it fails on the half that moved.
- **Every pack change must be mirrored into `examples/second-pack`**, or
  `tests/test_second_pack.py:520` (`test_no_key_in_a_pack_table_is_read_by_nothing`)
  fails.
- **Do not put new code under `manuscript_harvest/extract/`.** `source_fingerprint()`
  globs `extract/*.py` into `extraction_key`
  (`manuscript_harvest/extract/__init__.py:9-30`), so a file added there invalidates
  all 392 extractions.
- **`--output-format json` moves the text the abort sentinels grep.**
  `run_headless.sh:129,139` read `$log`; that guard is what stops a usage limit from
  burning the queue, and it already failed once at a cost of 145 spawns. Keep stdout
  and stderr separate, and read both the envelope and the log.
- **Any coverage sidecar needs a staleness stamp.** There is no `extraction_key`
  equivalent for a sidecar, and one that silently describes an older extraction is
  the same never-fires shape as the `source` filter at `pe/paper_text.py:167-176`.
- **`role` is the authoritative supplement discriminator and nothing uses it.**
  `pe/paper_text.py:175-176` matches on the `source_file` path string instead. It
  agrees with `role` on all 394,369 corpus blocks today, but only because

- **Two corpus trees.** Repo-root `corpus/` is real (392 papers, manifests, blocks).
  `.claude/skills/perturbation-detection/corpus/` holds 382 directories containing
  only `extracted/perturbations.json` — no manifests, no blocks. Passing it to a
  supplement check silently produces zero findings.
